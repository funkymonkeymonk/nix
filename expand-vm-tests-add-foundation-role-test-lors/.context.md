# Goal
Add a generic mkRoleVmTest generator to tests/vm/default.nix that auto-derives VM boot tests from each role's actual environment.systemPackages, instead of hand-writing a testScript per role. This produces vm-role-foundation and vm-role-developer, satisfying both originally-separate 'add foundation role test' / 'add developer role test' yaks (the latter closed and merged here).

# Why generic instead of hand-written
- Foundation role defaults to enable=true and runs on every host including all 5 NixOS hosts (zero, type-nas, type-server, type-server-arm, type-desktop) -- this is the one role every machine in the fleet actually depends on, and it's never been boot-tested.
- Developer role currently has no NixOS adopter (only library/archetypes/workstation-darwin.nix enables it) -- lower priority, but free to add once the generator exists.
- tests/test-roles.nix already hand-maintains a roleExpectedPackages map (line 97-111) that duplicates each role's package list and silently drifts when a role's packages.nix changes without a matching test update. The generator introspects the real module eval instead, so it can never drift.

# Design
```nix
mkRoleVmTest = role: let
  evaluated = (lib.evalModules {
    modules = mkTestModules ++ [{ config.myConfig.roles.${role}.enable = true; }];
  }).config;
  binaries = map (pkg: pkg.meta.mainProgram or pkg.pname or pkg.name)
    evaluated.environment.systemPackages;
in mkTest {
  name = "vm-role-${role}";
  roles = { ${role}.enable = true; };
  testScript = ''
    machine.wait_for_unit("multi-user.target")
  '' + lib.concatMapStringsSep "
" (b: ''machine.succeed("command -v ${lib.escapeShellArg b}")'') binaries;
};
```

Verified via `nix eval` against this repo's actual overlay (not plain nixpkgs) that meta.mainProgram correctly resolves every foundation/developer package, including our own custom packages:
helix->hx, jujutsu->jj, ripgrep->rg, nodejs->node, yaks->yx, rtk->rtk, pi-coding-agent->pi, delta->delta, gh->gh, jq->jq, clang->clang, python3->python3.14, yarn->yarn, gh-dash->gh-dash.
Zero manual binary-name override map needed.

# Acceptance Criteria
- [ ] `mkRoleVmTest` added to `tests/vm/default.nix`, reusing mkTest's exact module list for introspection (single source of truth -- no separate/parallel module list that could drift from what mkTest actually boots)
- [ ] Uses `command -v <bin>`, NOT `<bin> --version` -- presence-only check, no execution (avoids hang risk seen previously with GUI/Electron packages like logseq)
- [ ] `vm-role-foundation = mkRoleVmTest "foundation"` added and passes: `nix build .#checks.x86_64-linux.vm-role-foundation`
- [ ] `vm-role-developer = mkRoleVmTest "developer"` added and passes: `nix build .#checks.x86_64-linux.vm-role-developer`
- [ ] Both exported from tests/vm/default.nix alongside vm-users/vm-ssh/vm-packages
- [ ] Explicitly out of scope for this yak (future one-line extensions if wanted): gaming/entertainment/desktop/workstation (GUI-heavy, low value even with presence-only checks) and assistant/email-backup (Darwin/Homebrew-only, contribute nothing to NixOS environment.systemPackages)
