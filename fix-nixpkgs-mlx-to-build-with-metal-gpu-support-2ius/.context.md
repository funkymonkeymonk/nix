## Resolution (2026-08-22)

Closed -- already resolved. Two days after this yak was filed (2026-07-16), PR #359 (commit 63fa0ea, 2026-07-18) fixed this via packages/mlx-metal/default.nix, wired in via overlays/default.nix:24-33 (python3Packages.packageOverrides sets mlx = mlx-metal). It does NOT patch nixpkgs' mlx.nix -- it replaces it entirely with prebuilt PyPI wheels (mlx==0.32.0 + mlx_metal==0.32.0), since building mlx with Metal in the Nix sandbox requires an Xcode toolchain sandbox escape that isn't achievable here. Documented in docs/reference/llm-stack.md and docs/how-to/configure-llm-stack.md, including live verification (AGXMetalG13X.bundle mapped, 60+ tok/s on text-only requests).

**Follow-up risk (not filing a new yak for this now, just noting it):** the mlx-metal wheel pin (0.32.0) is tied to a specific Python minor version tag (cp3XX-macosx_15_0_arm64). Future nixpkgs Python version bumps or new MLX releases will require updating packages/mlx-metal/default.nix's version/hash. Revisit if a nixpkgs bump ever breaks the vllm-mlx build.
