# Goal
Move the `mkUser` helper out of `flake.nix`'s `outputs` let-block into its
own file, `library/lib/mk-user.nix`, so it can be imported both by
`flake.nix` (unchanged behavior for existing hosts) and by the new
`library/machines/zero.nix` flake-parts module (a later yak in this
series), which cannot reach into `flake.nix`'s local let-binding.

## Prerequisites
- None (first step)

# Design (from spec: docs/superpowers/specs/2026-08-22-zero-flake-parts-pilot-design.md)
`library/lib/mk-user.nix` should export the `mkUser` function verbatim:
```nix
name: email: {
  users = [
    {
      inherit name email;
      fullName = "Will Weaver";
      isAdmin = true;
      sshIncludes = [];
    }
  ];
  onepassword.enable = true;
  opencode = {
    enable = true;
    model = "opencode/big-pickle";
  };
  claude-code = {
    enable = false;
  };
  llmClient.rtk.enable = true;
}
```
Match the existing structure exactly (`{}: name: email: {...}` or plain
`name: email: {...}` — check how `flake.nix` currently binds `mkUser` at
line ~69 and preserve calling convention so `flake.nix`'s 5 existing
`extraSpecialArgs = {inherit mkUser;}` call sites and
`targets/zero/default.nix`'s use of `mkUser` need zero changes at their
call sites).

# Acceptance Criteria
- [ ] `library/lib/mk-user.nix` created, exporting `mkUser` with identical
      behavior to the current inline definition
- [ ] `flake.nix`'s inline `mkUser = name: email: {...}` definition removed,
      replaced with `mkUser = import ./library/lib/mk-user.nix;`
- [ ] All 5 existing `extraSpecialArgs = {inherit mkUser;}` call sites in
      `flake.nix` (wweaver, MegamanX, darwin-server, and others — grep to
      confirm the exact set) still work unchanged
- [ ] `devenv tasks run check:lint` passes
- [ ] `devenv tasks run test:all` passes (proves no host's eval broke)
- [ ] `nix eval` diff: the resulting `mkUser "monkey" "me@willweaver.dev"`
      output is byte-identical before/after (verify via
      `nix eval --json` comparison on at least one host that uses it)
