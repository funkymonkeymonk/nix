## Why
Same core article finding as wweaver's companion yak: Qwen3.8-27B defaults to
its most expensive reasoning setting and can burn huge token budgets on trivial
requests, silently exhausting context in long agent sessions. On MegamanX this
matters especially for `pi-subagents` fan-out (many parallel/short-lived agent
calls where per-call reasoning overhead multiplies) and for the
`vane.defaultModel = "qwen3.8-27b"` general-purpose chat use case, where most
turns don't need max reasoning depth.

## Current repo state
`hosts/megamanx/default.nix` pi `models.bifrost` already sets `reasoning =
false` / `supportsReasoningEffort = false` -- but this is a client-compat flag
for tool-calling reliability with THAT specific pi model entry, not a verified
effort-tuning mechanism, and it doesn't apply to Vane, opencode, or any other
consumer hitting the qwen3.8-27b model through Bifrost.

## What to do
1. Same investigation as the wweaver companion yak: does vllm-mlx support a
   server flag or a per-request `reasoning_effort`/`enable_thinking` API param?
2. If per-request: audit ALL consumers routed through Bifrost to qwen3.8-27b
   (Vane, opencode, pi's other model entries, pi-subagents) and ensure each
   sets a sane default reasoning effort for its use case rather than inheriting
   the model's expensive default
3. If server-side: this becomes a straightforward instance-options.nix +
   lib.nix addition, shared with the wweaver yak's implementation
4. Consider whether different MegamanX instances/ports should have different
   defaults -- e.g. low/medium effort on the interactive port 8300 for fast
   coding-agent turnaround, higher effort available on-demand (per-request
   override) for genuinely hard planning tasks
