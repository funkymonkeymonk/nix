# Goal
Delete both `nixosConfigurations.zero` and `zero-v2` outright. Replace with a
flake-parts composite system (per the Phase 8 flake-parts wiring goal) rather
than patching zero-v2 to parity and renaming it. This makes zero the first
real-world proof of the flake-parts composition model instead of just another
mkNixosSystem wrapper.

# Background
Comparison of the two existing outputs found `zero-v2` is NOT a safe drop-in
replacement for `zero`:
- `zero-v2` is missing `opnix.nixosModules.default` at the system level
  (only home-manager's opnix module is wired via `mkNixosSystem`) — system-level
  1Password secrets (sudo password, SSH keys via opnix) would not activate.
- `zero-v2` uses the generic `disk-configs/single-disk-ext4.nix` instead of
  zero's actual hardware-specific `disk-configs/zero.nix` (NVMe, 1G ESP, 17G
  swap) — applying zero-v2 as-is would misconfigure disk layout on real hardware.
- `zero-v2` sets `autoUpgrade.flakeUrl = "...#zero-v2"`, which is itself a
  smell — a real machine's auto-upgrade target shouldn't reference a "-v2"
  scratch name.

Rather than fix these two gaps in-place and rename zero-v2 -> zero (patch-and-swap),
this yak's goal is to use zero as the pilot for actually wiring flake-parts
(the Phase 8.3 goal) — composing zero from library archetypes + machine
overrides through a flake-parts module, since zero already has home-manager,
opnix, disko, and a real machine type — a representative test case for the
instance-flake-generation motivation described in the Phase 8 parent yak.

## Prerequisites
- Flake decomposition: Phase 8 — cleanup / 8.3 (wire flake-parts into flake.nix) should
  land first, OR this yak can pioneer that wiring if 8.3 hasn't started yet — coordinate
  before starting.

# Acceptance Criteria
- [ ] `nixosConfigurations.zero` and `zero-v2` both removed from flake.nix
- [ ] zero is composed via a flake-parts module (not a raw nixosSystem / mkNixosSystem call
      in flake.nix directly) — library archetypes (desktop-nixos) + machine overrides
      (disk-configs/zero.nix, machine-types/desktop.nix or equivalent)
- [ ] opnix wired at BOTH system level (`opnix.nixosModules.default`) and home-manager level
      — verify this isn't just inherited from the old zero and lost again
- [ ] Correct hardware-specific disk config used (NOT single-disk-ext4.nix generic stub)
- [ ] autoUpgrade.flakeUrl points at whatever the final flake-parts output is actually named
      (no "-v2" or scratch suffix)
- [ ] `devenv tasks run test` passes
- [ ] Verified on actual zero hardware before calling this done — see Hardware Verification
      story in the yak backlog for precedent (@needs-human confirmation required)
- [ ] `modules/common/scripts/nix-cloud-init` nixos_items list updated if the output name changes

This is a live, currently-running machine. Do not apply directly to hardware without
building and reviewing the derivation diff first (`nix store diff-closures`), and get
explicit human sign-off before switching real hardware.
