## Prerequisites / relationship to sibling yaks
This is the concrete resolution path if "Investigate MTP + continuous-
batching/prefix-cache compatibility" finds them incompatible, and an
alternative to "Try native enableMtp path" if that doesn't pan out. Not
strictly @blocked on either -- can be evaluated independently since it doesn't
touch the existing qwen (8300) or gemma (8301) instances.

## Why
MegamanX has ~40GB of unused RAM headroom (88GB budgeted of 128GB total).
The existing qwen instance is optimized for single-stream interactive speed
(MTP speculative decoding, SimpleEngine, no prefix cache -- full re-prefill of
the ~36,000-token skill-heavy system prompt on every request per
docs/reference/llm-stack.md's "System Prompt Inventory"). That's a good
tradeoff for one interactive chat, but MegamanX also drives multiple
concurrent agent workloads (opencode, pi, pi-subagents per
hosts/megamanx/default.nix's `pi.npmPackages."pi-subagents"`) that would
benefit far more from BatchedEngine + prefix-cache reuse of that same repeated
system prompt than from MTP's single-stream speedup.

## What to do
Add a third named instance (pattern: `myConfig.vllmMlxInstances.<name>`, same
as the existing `gemma` instance) on a new port (e.g. 8302):

```nix
vllmMlxInstances.qwen-batched = {
  enable = true;
  server = { host = "0.0.0.0"; port = 8302; };
  memoryBudgetGb = 24;                    # 4-bit model is ~18GB
  contention = "preempt";
  models."qwen3.8-27b-batched" = {
    path = "mlx-community/Qwen3.8-27B-4bit";  # already pre-fetched overlay
    type = "lm";
    estimatedMemoryGb = 18;
    preload = true;
  };
  enableAutoToolChoice = true;
  toolCallParser = "qwen";
  reasoningParser = "qwen3";
  maxKvSize = 131072;
  timeout = 600;
  enableMetrics = true;
  enableContinuousBatching = true;
  enablePrefixCache = true;
  chunkedPrefillTokens = 0;  # crash workaround, same as gemma instance
};
```

Wire it into Bifrost as a second qwen upstream (`vllm-mlx-qwen-batched`) and
consider routing pi-subagents traffic there specifically, while interactive
opencode/pi main-session traffic stays on the MTP-accelerated port 8300.

## Acceptance criteria
- [ ] New instance added and reachable on its own port
- [ ] Bifrost upstream wired so subagent traffic can target it explicitly
- [ ] Repeated-system-prompt benchmark shows prefix-cache reuse working
      (second+ request with same system prompt is measurably faster than first)
- [ ] `devenv tasks run check:lint` and `test:build-checks` pass
- [ ] docs/reference/llm-stack.md updated with the new port/instance
