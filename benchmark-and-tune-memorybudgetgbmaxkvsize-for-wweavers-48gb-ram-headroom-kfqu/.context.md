## Why
The base install yak proposes conservative starting values (memoryBudgetGb=24,
maxKvSize=65536) chosen without real measurement. 48GB is a hard ceiling shared
with the OS, browser, IDE, and opencode/pi itself — unlike MegamanX's 128GB where
there's 40GB of slack even at 88GB budgeted. Getting this wrong on a laptop means
either wasted headroom (small context window that gets hit during long agent
sessions -- the article specifically warns this "can quietly exhaust the context
window and return empty output that looks like an unrelated error") or system-wide
swapping/thermal throttling during normal laptop use.

## What to do
1. With the base Qwen3.8-27B-4bit instance running, drive representative agentic
   coding-session prompts (long tool-call chains, large repo context) through it
   while running normal daily-driver apps (browser, editor, Slack, etc.)
2. Watch `vm_stat`/Activity Monitor for swap/compression pressure at increasing
   maxKvSize values (65536 -> 98304 -> 131072) and increasing memoryBudgetGb
3. Pick the largest maxKvSize that doesn't cause noticeable swap pressure during
   normal multitasking; document the chosen values with a comment in
   hosts/wweaver/default.nix explaining the tradeoff (mirror the style of
   existing comments in hosts/megamanx/default.nix)
4. Consider whether `contention = "wait"` is safer than `preempt` on a
   single-model laptop instance (no second model competing for the budget, so
   the practical difference is small, but confirm)

## Acceptance criteria
- [ ] Documented (in commit message / nix comment) the max maxKvSize that avoids

- [ ] hosts/wweaver/default.nix updated with the measured values
