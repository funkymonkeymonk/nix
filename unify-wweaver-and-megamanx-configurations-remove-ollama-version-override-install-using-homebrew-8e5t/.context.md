# Goal

Unify wweaver (work laptop) and megamanx (personal desktop) configurations by:
1. Moving both to the archetype pattern (developer-laptop-darwin + workstation-darwin)
2. Removing the ollama version override from wweaver (or explaining why it's needed)
3. Using homebrew to install ollama instead of via Nix packages (wweaver already does this)
4. Simplifying machine-specific config to only override what differs

## Prerequisites

- None — this is a standalone refactor

## Current State

### wweaver (work laptop)
- No archetype (full inline config)
- Uses vane with LiteLLM gateway (justworksai.net)
- Roles: developer, workstation, opencode, pi, developer-laptop-darwin (implied?)
- Skills: superpowers only
- Vane pointing at Justworks LiteLLM gateway
- Pi plugins enabled

### megamanx (personal desktop)  
- Uses workstation-darwin archetype
- Full local LLM stack: vllm-mlx + bifrost + searxng + caddy
- Roles: entertainment (beyond workstation-darwin)
- Skills: superpowers only
- Complex LLM setup for local inference with tool calls
- Extensive Pi configuration and custom skills

## Acceptance Criteria

- [ ] Both wweaver and megamanx use archetypes (developer-laptop-darwin or workstation-darwin)
- [ ] Removed dead ollama overrides/version pins if they exist  
- [ ] Both use homebrew for ollama (not Nix packages)
- [ ] Each host config is <150 lines (thin — overrides only)
- [ ] Verified both evaluate cleanly: `nix eval .#darwinConfigurations.{wweaver,megamanx}.config`
- [ ] No behavior changes for either machine (both must still build)

## Key Decision

**Should developer-laptop-darwin archetype exist, or should wweaver use workstation-darwin?**
- workstation-darwin = both work + personal use
- developer-laptop-darwin = implies work-focused developer role only

Recommend: Create developer-laptop-darwin with developer + workstation roles both enabled, pointing at office infrastructure (LiteLLM, etc.). wweaver uses it; megamanx uses workstation-darwin.

## Risks

1. **Breaking wweaver's vane config** — ensure LiteLLM endpoint + auth survive the refactor
2. **PI plugins** — ensure pi-plugins input flows through archetype properly
3. **Machine-specific overrides** — sudo password ref, vane endpoint must stay machine-local
