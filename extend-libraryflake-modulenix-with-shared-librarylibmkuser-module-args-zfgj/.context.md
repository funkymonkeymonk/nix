# Goal
`library/flake-module.nix` currently only re-exports `modules/` as
`flake.nixosModules.library` and is imported nowhere. Extend it to also
provide `libraryLib` (the `mkNixosSystem`/`mkDarwinSystem` helpers from
`library/lib/mk-system.nix`) and `mkUser` (from `library/lib/mk-user.nix`)
as shared flake-parts module args (`_module.args`), so
`library/machines/zero.nix` (next yak) and any future per-machine module
can consume them with zero boilerplate instead of each re-deriving
`libraryLib` from scratch.

## Prerequisites
- "Extract mkUser helper into library/lib/mk-user.nix" must be done first

# Design (from spec: docs/superpowers/specs/2026-08-22-zero-flake-parts-pilot-design.md)
```nix
{inputs, ...}: {
  flake.nixosModules.library = {
    imports = [
      (import ../modules)
    ];
  };

  _module.args.libraryLib = import ./lib/mk-system.nix {lib = inputs.nixpkgs.lib;};
  _module.args.mkUser = import ./lib/mk-user.nix;
}
```
Note this file's current signature is `_: {...}` (ignores its args) —
it needs to change to take `inputs` since `mk-system.nix` needs `lib` and
this is the natural place to derive it consistently with how `flake.nix`
does it today (`inherit (nixpkgs) lib; libraryLib = import
./library/lib/mk-system.nix {inherit lib;};`).

This file is a flake-parts module, so `_module.args.*` here uses standard
flake-parts/NixOS-module-system semantics — verify this actually
propagates to sibling modules imported alongside it in the same
`mkFlake` call (it should, per flake-parts docs, since `_module.args` is
standard module-system module-argument injection, not per-file scoped).
