## Problem
Discovered while fixing documentation drift (2026-07-27):
`modules/roles/agent-skills.nix` declares its own option at
`options.myConfig.agent-skills.enable` and gates its config on
`cfg = config.myConfig.roles.agent-skills` (note: `.roles.` in the path).
These are two DIFFERENT, independently-defined options:

- `modules/common/options.nix` defines `myConfig.roles.agent-skills.enable`
  (nested under the `roles = { ... }` block, default false)
- `modules/roles/agent-skills.nix` separately defines
  `myConfig.agent-skills.enable` (NOT nested under roles, default false)

Other roles (opencode.nix, claude.nix, pi.nix) set
`myConfig.agent-skills.enable = true;` (the flat path) when they're
enabled. But `agent-skills.nix`'s own `mkIf cfg.enable` reads
`myConfig.roles.agent-skills.enable` (the nested path) -- which is NEVER
set to true anywhere. Result: the shell aliases this module provides
(`skills-status`, `skills-update`, `skills-list`) and the
`AGENT_SKILLS_PATH`/`SUPERPOWERS_SKILLS_PATH` env vars never actually
get installed on any real machine.

## Evidence
```
nix eval .#darwinConfigurations.wweaver.config.myConfig.agent-skills.enable
# => true

nix eval .#darwinConfigurations.wweaver.config.myConfig.roles.agent-skills.enable
# => false

nix eval .#darwinConfigurations.wweaver.config.environment.shellAliases
# does NOT contain "skills-list"
```

## Likely Fix
Change `modules/roles/agent-skills.nix`'s `cfg` binding from
`config.myConfig.roles.agent-skills` to `config.myConfig.agent-skills`
(dropping `.roles.`), matching how opencode.nix/claude.nix/pi.nix already
set it. This makes the module's own `options.myConfig.agent-skills.enable`
declaration and its `cfg` read consistent.

Also consider: should `myConfig.roles.agent-skills.enable` (declared in
modules/common/options.nix) be removed entirely, since nothing sets or
reads it correctly today? Or should the module move to use the roles-
namespaced option consistently instead? Either fix closes the gap --
just pick one canonical path and make declaration + consumption + all
setters agree.
