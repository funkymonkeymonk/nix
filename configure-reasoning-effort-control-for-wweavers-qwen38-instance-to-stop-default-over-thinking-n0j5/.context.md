## Why (core finding of the source article)

"Qwen3.8-27B thinks by default, and its default reasoning setting is the most
expensive one available. Left alone, it will burn tens of thousands of reasoning
tokens on requests a human would answer in one sentence. In long agent sessions,
that same verbosity can quietly exhaust the context window and return empty
output that looks like an unrelated error." This is called the #1 setting that
determines whether a local Qwen3.8-27B setup feels frontier-adjacent or unusably
slow/verbose.

This matters MORE on wweaver than MegamanX because wweaver has a much smaller
memory/context budget (see the benchmark-tuning yak) — wasted reasoning tokens
eat directly into a scarcer maxKvSize.

## Current repo state
No `reasoning_effort` / `enable_thinking` option exists anywhere in
modules/services/vllm-mlx/. MegamanX's pi config sets `reasoning = false` /
`supportsReasoningEffort = false` on the client (pi) side for its Bifrost-routed
model, but that's about display/compat, not effort tuning, and there's no
evidence it actually caps the model's internal thinking budget.
