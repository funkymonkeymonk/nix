# Goal
Convert `flake.nix`'s `outputs` from a plain lambda to
`flake-parts.lib.mkFlake`, with every host except `zero` staying defined
exactly as today inside the `flake = { ... }` passthrough. Create
`library/machines/zero.nix` as a flake-parts module that defines
`flake.nixosConfigurations.zero`, and remove the inline `zero` block from
`flake.nix`'s manual `nixosConfigurations` attrset.

## Prerequisites
- "Extend library/flake-module.nix with shared libraryLib/mkUser module args"
  must be done first

# Design (from spec: docs/superpowers/specs/2026-08-22-zero-flake-parts-pilot-design.md)

`library/machines/zero.nix`:
```nix
{libraryLib, mkUser, inputs, ...}: {
  flake.nixosConfigurations.zero = libraryLib.mkNixosSystem {
    inherit inputs;
    hostname = "zero";
    extraSpecialArgs = {inherit mkUser;};
    modules = [
      ../archetypes/desktop-nixos.nix
      ../../modules/nixos/base.nix
      ../../modules/nixos/desktop.nix
      ../../modules/nixos/gaming.nix
      ../../modules/nixos/streaming.nix
      ../../os/nixos.nix
      inputs.disko.nixosModules.disko
      ../../disk-configs/zero.nix
      ../../machine-types/desktop.nix
      ../../modules/nixos/ghostty-terminfo.nix
      ../../targets/zero
    ];
    overrides = {
      autoUpgrade.flakeUrl = "github:funkymonkeymonk/nix#zero";
    };
  };
}
```
(Verify relative paths carefully — this file lives in
`library/machines/`, two directories deeper than `flake.nix`, so every
relative import in the current inline block at flake.nix:231-252 needs
its `./` prefix recalculated to `../../` etc. Get this exactly right or
the build will fail with a clear missing-file error — cheap to verify.)

`flake.nix` outputs becomes:
```nix
outputs = inputs @ {
  self,
  nixpkgs,
  flake-parts,
  ...
}:
  flake-parts.lib.mkFlake {inherit inputs;} {
    systems = ["aarch64-darwin" "x86_64-linux"];
    imports = [
      ./library/flake-module.nix
      ./library/machines/zero.nix
    ];
    flake = {
      # ...everything currently in outputs EXCEPT the zero block in
      # nixosConfigurations, unchanged...
    };
  };
```
Exact shape of `mkFlake`'s two-argument vs one-argument call signature
needs verification against the pinned `flake-parts` input version — check
`flake-parts` docs/README for the current API before writing this (API
has had minor signature changes across versions; this repo pins
`github:hercules-ci/flake-parts` unpinned to a rev, so use whatever
version `nix flake metadata` resolves).

Remove the `# zero — Gaming/desktop NixOS machine` block (currently
flake.nix lines ~231-252) from the manual `nixosConfigurations` attrset
entirely — it now lives in `library/machines/zero.nix`.

- [ ] `library/machines/zero.nix` created with correct relative paths to
      all modules zero depends on (archetype, disk config, machine-type,
      targets/zero, etc.) — identical module list to what's in flake.nix
      today, just relocated
- [ ] `flake.nix`'s `outputs` uses `flake-parts.lib.mkFlake`

      `./library/machines/zero.nix`

- [ ] Every other host (wweaver, MegamanX, darwin-server, type-nas,

# Notes
This is the core, highest-risk yak in the series — it's the only one
that touches `flake.nix`'s top-level structure. If `flake-parts.lib.mkFlake`
behaves unexpectedly (unrecognized `systems` list, unexpected extra
outputs like `checks.<system>.someFlakePartsDefault`, etc.), STOP and
re-scope rather than force it — per this repo's brainstorming/systematic-debugging
norms, hidden complexity here should escalate back for review, not be
silently worked around.

No hardware switch — this is build/eval verification only.
