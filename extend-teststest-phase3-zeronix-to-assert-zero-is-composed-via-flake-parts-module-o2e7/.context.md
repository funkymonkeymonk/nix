# Goal
Extend `tests/test-phase3-zero.nix` to keep its existing "zero exists /
zero-v2 retired" assertions, and add a structural regression guard
asserting `zero` is now composed via the flake-parts module path
(`library/machines/zero.nix`) rather than defined inline in `flake.nix`.
This prevents a future refactor from silently moving zero back to an
inline definition without anyone noticing.

## Prerequisites
- "Create library/machines/zero.nix and wire flake-parts into flake.nix
  outputs" must be done first

# Design (from spec: docs/superpowers/specs/2026-08-22-zero-flake-parts-pilot-design.md)
Current file only checks `self.nixosConfigurations` attribute presence
(behavioral, not structural). Add a check using `builtins.readFile` or
`builtins.pathExists` against the repo source (this test already has
access to source-tree-relative checks — verify pattern against other
structural tests in this repo, e.g. how `tests/test-coverage.nix` or
similar checks file existence) to assert:
1. `library/machines/zero.nix` exists
2. `flake.nix` does NOT contain an inline `"zero" = libraryLib.mkNixosSystem`
   pattern (a simple `builtins.match` or substring check against
   `builtins.readFile ../flake.nix` is sufficient — don't over-engineer
   with an AST parse)

Keep the existing `zero: defined` and `zero-v2: retired` checks
unchanged — they're still valid and already passing.
