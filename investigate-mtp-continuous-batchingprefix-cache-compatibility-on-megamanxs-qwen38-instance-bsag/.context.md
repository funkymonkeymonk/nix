## Why
docs/reference/llm-stack.md's Known Issues table documents: "Prefix cache not
in SimpleEngine (vllm-mlx#567, PR #574 open) — No cross-turn prefix reuse in
default mode — Workaround: Use enableContinuousBatching = true." But MegamanX's
qwen instance uses `mllmDraftModel` for MTP speculative decoding, and per
instance-options.nix's own doc comment, setting `mllmDraftModel` "forces
single-model mode" (drops `--models-config`). It is NOT documented anywhere
whether `--mllm-draft-model` (external draft MTP) is also incompatible with
`--continuous-batching`/`--enable-prefix-cache` at the vllm-mlx CLI/engine level,
or whether single-model-mode and BatchedEngine-mode are actually orthogonal.

Today MegamanX's qwen instance gets MTP speed but NO prefix-cache reuse of the
~36,000-token system prompt documented in llm-stack.md ("System Prompt
Inventory" section) across agent turns/dispatches — every request currently
re-prefills the full skill-heavy system prompt from scratch on the qwen port,
which is likely a bigger latency cost than MTP saves for short-completion tool
calls.

## What to do
1. Check upstream waybarrios/vllm-mlx source (pinned commit 61c78dc0 in
   packages/vllm-mlx/default.nix) or its CLI arg parser for hard incompatibility
   assertions between `--mllm-draft-model` and `--continuous-batching`/
   `--enable-prefix-cache`
2. If compatible: try enabling `enableContinuousBatching = true` +
   `enablePrefixCache = true` + `chunkedPrefillTokens = 0` (matching the
   existing crash workaround already used by the gemma instance) on the qwen
   instance alongside the existing `mllmDraftModel` config; benchmark repeated
   system-prompt-prefix requests before/after
3. If incompatible: this is a deliberate tradeoff to surface explicitly (fast
   single-stream decode via MTP vs. prefix-cache reuse for repeated ~36k-token
   agent system prompts) — document the choice and consider the companion
   "Add a batched, non-MTP instance" yak as the resolution instead (i.e. keep
   MTP on the primary port for interactive single-turn speed, add a second
   batched port specifically for repeated-system-prompt agent dispatch/subagent
   traffic)
