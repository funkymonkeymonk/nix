## Background

Source: https://linas.substack.com/p/qwen3-8-27b-local-guide (paywalled after intro).
Free-preview facts used below:
- Qwen3.8-27B: dense 27B model, ALL params active every token, Apache 2.0, 262144-token
  native context, vision-capable.
- 4-bit quant compresses to ~17-18GB on disk (fits a 24GB GPU or mid-range Apple Silicon Mac).
- **Biggest local-perf trap: the model "thinks" by default at its most expensive reasoning
  setting.** Left alone it burns huge reasoning-token budgets on trivial requests and can
  silently exhaust the context window in long agent sessions. Deliberately setting
  reasoning effort / context window is called out as the #1 fix.
- Article promises (teased, not fully visible): hardware/quant decision table (8GB laptop
  through 48GB workstation), launch flags for MTP speculative decoding + KV cache precision
  + chat template handling worth 2-3x speed, and deployment walkthroughs for llama.cpp/
  Ollama/LM Studio/vLLM/SGLang.

- `hosts/megamanx/default.nix` ("the other stack studio w/ 128GB RAM"): already runs
  vllm-mlx with Qwen3.8-27B-8bit (default instance, port 8300, memoryBudgetGb=64,
  MTP speculative decoding via external `mlx-vlm` draft model
  `mlx-community/Qwen3.8-27B-MTP-8bit`, maxKvSize=131072) + a second Gemma 4 e4b
  BatchedEngine instance (port 8301, memoryBudgetGb=24). Total budgeted: 88/128GB.
- Module: `modules/services/vllm-mlx/{instance-options.nix,lib.nix,darwin.nix,
  darwin-instances-options.nix,darwin-instances-config.nix}`. Package:
  `packages/vllm-mlx/default.nix`. Pre-fetched model overlays in
  `overlays/default.nix:36-65` already include BOTH 8bit and 4bit Qwen3.8-27B
  variants and their MTP draft models (qwen3_8-27B-{4,8}bit,
  qwen3_8-27B-MTP-{4,8}bit) — no new fetchModel derivation needed for any yak below.
- `instance-options.nix` exposes two *different* MTP mechanisms:
  1. `enableMtp`/`mtpNumDraftTokens`/`mtpOptimistic` — built-in MTP head, compatible
     with multi-model `--models-config` registry.
  2. `mllmDraftModel`/`mllmDraftKind`/`mllmDraftBlockSize` — external mlx-vlm draft
     model; **forces single-model mode** (incompatible with `--models-config`).
  MegamanX today uses mechanism #2 (external draft model), not #1.
- No KV-cache-precision option exists anywhere in the module today.
- No reasoning-effort option exists anywhere in the module; the only related knob is
  client-side `reasoning = false` / `supportsReasoningEffort = false` in
  `hosts/megamanx/default.nix` pi `models.bifrost` (disables reasoning display for
  tool-calling reliability, not effort tuning).
- `docs/reference/llm-stack.md` "Target Configuration" example is stale — still shows
  `qwen3.6-35b` / `memoryBudgetGb = 32`, no MTP, no gemma instance, no wweaver.
- Known upstream issues already documented: prefix-cache+large-prompt crash
  (workaround `chunkedPrefillTokens = 0`), prefix cache NOT available in SimpleEngine
  (workaround: `enableContinuousBatching = true`, ~10-20% per-request throughput cost).
