## Problem

Discovered while implementing 'Add architecture diagrams to explanation
docs' and 'Auto-generate options.md from Nix code' (2026-07-28):
scripts/docs-update.sh's generate_roles_reference,
generate_tasks_reference, and generate_skills_reference functions all
log messages claiming to generate docs "from modules/roles/",
"from devenv.nix", and "from manifest.nix" respectively -- but they
actually just heredoc a fully HARDCODED, stale template into the
target file. None of them parse the source they claim to read.

This is almost certainly the ROOT CAUSE of the extensive documentation
drift fixed in PR #373 ('Fix critical documentation drift across
reference docs'): running `devenv tasks run docs:generate` (or
`docs:update`, which calls it) would silently OVERWRITE those manual
fixes with the exact same stale content that was just fixed --
fictional "base" role, fictional devenv tasks (switch/build/build:all/
quality), fictional llm-client/llm-claude skill roles, etc.

## Evidence
- generate_roles_reference (scripts/docs-update.sh:132) hardcodes a
  role list including "base" (doesn't exist; real always-on role is
  "foundation") and case-statement descriptions that don't match
  modules/roles/*.nix
- generate_tasks_reference (scripts/docs-update.sh:322) hardcodes the
  exact same fictional task list fixed in PR #373: switch, init,
  build, build:darwin, build:nixos, build:all, quality, fmt, ide,
  pr:review, cachix:push, git:set-remote-ssh, etc. -- none of which
  exist in devenv.nix's actual "..." = { ... }; task definitions
- generate_skills_reference (scripts/docs-update.sh:455) hardcodes the
  exact same stale 11-skill table (vs the real 23 skills) with fake
  llm-client/llm-claude roles fixed in PR #373

## Likely Fix
Rewrite all three functions to actually parse their claimed source:
- generate_roles_reference: read modules/roles/*.nix files, extract
  descriptions from leading comments, package lists from
  environment.systemPackages, cascade options from mkIf blocks (or
  accept this is hard to fully automate and instead just validate
  that the doc's role list matches `ls modules/roles/*.nix`, erroring
  if they diverge, rather than trying to regenerate rich prose)
- generate_tasks_reference: parse devenv.nix's `tasks = { "name" = {
  description = "..."; ...}; }` attrset (could shell out to
  `nix eval .#devShells.<system>.default.??? ` or grep the quoted
  task names + description strings directly, which is what PR #373's
  manual fix effectively did by hand)
- generate_skills_reference: parse
  modules/home-manager/skills/manifest.nix's attrset (grep-based
  extraction of name/description/roles per entry, or a small
  `nix eval` one-liner against the manifest file directly -- this one
  is the most tractable since it's pure Nix data)

At minimum, each function should FAIL LOUDLY (non-zero exit) if its
generated content doesn't match the real source, rather than silently
overwriting good docs with fiction.

## Acceptance Criteria
- [ ] generate_roles_reference actually reflects modules/roles/*.nix
      (real role list, no fictional "base")
- [ ] generate_tasks_reference actually reflects devenv.nix's real
      task names (parsed, not hardcoded)
- [ ] generate_skills_reference actually reflects
      modules/home-manager/skills/manifest.nix's real skill count/roles
- [ ] Running `devenv tasks run docs:generate` on the current repo
      state produces output that MATCHES the manually-fixed content
      from PR #373 (or is a strict superset/improvement), not a
      regression back to the old fiction
- [ ] devenv tasks run check:lint and devenv tasks run test pass
