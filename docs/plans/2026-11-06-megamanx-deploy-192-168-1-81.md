# MegamanX Deployment Plan

> **Note:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute this plan task-by-task.

**Goal:** Apply the catalogued nix-darwin configuration `MegamanX` to the host at `192.168.1.81` and verify its core services without losing a recovery path.

**Architecture:** Use the repository's named devenv Machines operations against the already configured local SSH endpoint. Review a single-machine plan before applying it; do not use the workstation's `system:switch` task or install/partition workflows. Keep the existing host generation and a trusted console/SSH recovery path available during activation.

**Tech Stack:** Nix flake, devenv Machines tasks, nix-darwin, SSH, SecretSpec/1Password.

---

## Scope and known configuration

- The canonical machine is `MegamanX` (`aarch64-darwin`) in `library/machines/catalog.nix`, composed from `library/archetypes/headless-inference-darwin.nix` and catalog overrides.
- The ignored `devenv.local.nix` already maps `machines.MegamanX.target.host` to `monkey@192.168.1.81`; no endpoint edit is planned.
- This is a nix-darwin **deployment**, not a fresh install. Do not run `machines:install`, `system:switch`, or any disk operation.
- The host enables SSH password authentication while preserving public-key authentication. Prefer the configured SSH key; do not disable host-key verification or put passwords on command lines.
- Temporal has been removed from MegamanX. Do not expect or deploy a Temporal service/UI as part of this configuration.

## Vault references

MegamanX uses `Opnix` as its default vault. The `MegamanX Sudo Password/password` reference is unqualified so the shared `devenv` task resolver prefixes that default vault; the MegamanX SecretSpec profile also routes through `Opnix`. The sudo-password item has been moved to `Opnix`. Keep credentials reference-only: do not fetch, print, or copy the password into the plan or shell history.

## Task 1: Confirm the local source and prerequisites

**Files:** None expected. Only modify the host/reference and SecretSpec configuration if the owner resolves the gate above and approves that change.

1. Confirm the checkout is at the intended committed revision and there are no unrelated pending changes. Nix flake operations must use the intended committed tree.
2. Confirm the local endpoint remains exactly `monkey@192.168.1.81` in ignored `devenv.local.nix`; do not copy this personal endpoint into a tracked file.
3. Confirm the host is the expected MegamanX device and that `192.168.1.81` is still its reserved/current address.
4. From a trusted channel or existing known-host record, verify the SSH host key. Do not accept a new or changed fingerprint without independent verification.
5. Confirm an SSH key is available and has access as `monkey`; use an SSH connection with strict host-key checking. Keep a local/physical console recovery path available.

**Gate:** If host identity, SSH access, address reservation, or a recovery path is missing, stop here.

## Task 2: Evaluate the named configuration without activating it

After the vault gate is resolved:

1. Run a named configuration build/evaluation:

   ```sh
   devenv tasks run machines:build --input machine=MegamanX
   ```

   This host is `aarch64-darwin`. Run the build on a compatible controller or use the repository's configured matching builder; if no supported builder is available, stop and arrange one rather than treating a failed cross-platform build as success.

2. Run the named remote preflight check:

   ```sh
   devenv tasks run machines:check --input machine=MegamanX
   ```

3. Review all output for the exact target, `aarch64-darwin` system, SSH/host-key issues, missing dependencies, and secret-resolution errors. Do not switch to another machine or disable strict SSH checks to bypass a failure.

**Expected:** The MegamanX configuration evaluates/builds and the remote check identifies the single intended target at `192.168.1.81`. No activation has happened yet.

**Stop conditions:** Wrong host, stale plan/target metadata, a build/evaluation error, an unexpected SSH fingerprint, failed authorization, or unresolved secrets. Fix the cause with owner approval and rerun the named checks; never substitute a broad/all-machines operation.

## Task 3: Generate and review a single-machine deployment plan

1. Generate the plan:

   ```sh
   devenv tasks run machines:plan --input machine=MegamanX
   ```

2. Record the emitted plan ID and inspect the saved plan under `.devenv/machine-plans/<plan-id>/plan.json`. Confirm it contains exactly one machine, `MegamanX`. Confirm the endpoint separately from the ignored `devenv.local.nix` mapping and the successful remote check; do not assume the plan JSON records the SSH address.
3. Review the proposed activation, package/service changes, and any restarts. Confirm the currently active system generation and that a rollback path is available.
4. If the plan is stale, targets another machine, or shows unexpected changes, do not apply it. Regenerate and review a fresh plan.

**Expected:** A reviewed plan exists for only `MegamanX`; its plan ID is available for the apply task.

## Task 4: Apply the reviewed plan

Apply only the plan ID reviewed in Task 3:

```sh
devenv tasks run machines:apply \
  --input machine=MegamanX \
  --input planId=<reviewed-plan-id>
```

Allow activation to complete; do not pass `yes=true` to a different deployment path or apply a plan generated for another host. If activation fails or SSH becomes unavailable, stop further operations and use the existing console/recovery path to inspect the active generation and roll back before retrying.

## Task 5: Verify services and finish first-time enrollment if needed

From SSH or the local console on MegamanX, verify the system and core services:

```sh
sudo launchctl print system/com.tailscale.tailscaled
sudo launchctl print system/org.prometheus.node-exporter
sudo launchctl print system/com.bifrost.tailscale-serve
curl --fail http://127.0.0.1:8081/v1/models
```

Also verify the oMLX service is healthy using the configured launchd label/status and inspect its logs if needed. Confirm SSH remains reachable at `192.168.1.81`, no Temporal service is configured, and the node exporter is bound only as configured.

If this is the first Tailscale enrollment, complete the owner-authorized interactive enrollment and follow `docs/how-to/enroll-megamanx-in-tailscale.md`. Do not place an auth key in command history or Nix configuration. Verify tailnet access from `drlight` and the metrics endpoint as described in that guide.

**Completion criteria:** The reviewed `MegamanX` plan applied successfully; SSH remains reachable; Bifrost responds locally; expected launch daemons are running; and any required Tailscale enrollment and remote telemetry checks are complete.

## Validation boundary

This is a production deployment plan, so local CI must not contact or deploy to the real host. If any tracked configuration changes are approved to resolve the vault issue, validate those changes separately before production use with:

```sh
devenv tasks run check:lint
devenv tasks run test:build-checks
devenv tasks run test:eval
```

Do not commit a deployment plan or configuration change with secrets, resolved secret values, private SSH keys, or the personal endpoint from `devenv.local.nix`.
