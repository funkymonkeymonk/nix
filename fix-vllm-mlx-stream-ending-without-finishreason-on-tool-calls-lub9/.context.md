# Goal
pi errors with "Stream ended without finish_reason" on tool calls via vllm-mlx + gemma4-31b.
Root cause (reproduced with curl replay of the exact failing request direct against :8300):
in vllm_mlx/server.py stream_chat_completion, the engine's terminal output (finished=True,
carrying the <tool_call|> end marker) is swallowed by the tool parser's `continue`, so no
SSE chunk ever carries finish_reason. Stream ends tool_calls(finish_reason=null) -> [DONE].
Upstream v0.4.0 (latest) has no fix.

# Acceptance Criteria
- [ ] Package carries a patch that emits a terminal finish_reason chunk when the engine's
      finished output was suppressed by a parser (tool_calls if detected, else stop/length)
- [ ] Regression test in tests/ proving a finished-but-swallowed stream still ends with a
      finish_reason chunk (RED first: fails on unpatched package)
- [ ] devenv tasks run check:lint passes
- [ ] Live verification: replay payload against patched server on scratch port returns
      finish_reason="tool_calls" before [DONE]
- [ ] PR opened; do not run system:switch (user applies)
