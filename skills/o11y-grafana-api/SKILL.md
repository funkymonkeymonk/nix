# Grafana API for This Repository

Use the Grafana HTTP API first. Do not SSH to `drlight` for dashboard or
datasource inspection.

## Connection

Use an `op run` environment file. Store references, not secret values, in the
file:

```bash
mkdir -p /tmp/opencode
cat > /tmp/opencode/grafana.op.env <<'EOF'
GRAFANA_URL=https://grafana.home.buildingbananas.com
GRAFANA_USER=op://Opnix/Grafana - Home/username
GRAFANA_PASSWORD=op://Opnix/Grafana - Home/password
EOF
```

Run the complete feedback session inside one `op run` process. This avoids
repeated credential reads and keeps resolved values out of files and logs:

```bash
op run --env-file=/tmp/opencode/grafana.op.env -- sh -c '
  curl -fsS -u "$GRAFANA_USER:$GRAFANA_PASSWORD" \
    "$GRAFANA_URL/api/health"
'
```

Do not print the environment or resolved credentials.

## API Development Workflow

Use this workflow for rapid dashboard feedback:

1. Fetch the provisioned dashboard with `/api/dashboards/uid/<uid>`.
2. Copy the exact target expressions and datasource UIDs.
3. Query each target through `/api/ds/query` with a narrow time range.
4. Inspect `results.<refId>.frames`, field names, row counts, labels, and errors.
5. Create a separate non-provisioned development copy with a new UID.
6. Update the development copy with `/api/dashboards/db`.
7. Re-query the changed targets and inspect the returned frames.
8. Copy the validated query into `modules/nixos/grafana.nix` for durable use.

Grafana rejects API writes to provisioned dashboards with `Cannot save
provisioned dashboard`. Do not use the API to overwrite the production UID.
Use a development UID such as `drlight-ultra-media-sync-dev` instead.

For a development copy, keep the complete fetched dashboard and remove its
`id`. Set its new `uid`, set `version` to `0`, and wrap it in the API body:

```bash
jq '(.dashboard
    | del(.id)
    | .uid = "drlight-ultra-media-sync-dev"
    | .version = 0) as $dashboard
  | {
      dashboard: $dashboard,
      folderId: 0,
      overwrite: true,
      message: "API development change"
    }' \
  dashboard-response.json > dashboard-update.json
```

Use `op run --env-file=... -- sh -c '...'` for both dashboard requests and
datasource queries.

Prometheus table panels that show current rows must set `instant: true` and
`range: false`. Give each target a stable `refId`. Range queries are sparse and
slow for per-entity tables because they return one time series per entity.

After you validate the API experiment, update the declarative Nix source and
deploy it through the repository's normal Machines plan/apply workflow.

## Dashboard API

The declarative Ultra dashboard has UID `drlight-ultra-media-sync`:

```bash
op run --env-file=/tmp/opencode/grafana.op.env -- sh -c '
  curl -fsS -u "$GRAFANA_USER:$GRAFANA_PASSWORD" \
    "$GRAFANA_URL/api/dashboards/uid/drlight-ultra-media-sync" | jq .
'
```

Use a payload with a datasource UID, a stable `refId`, and an explicit query
mode:

```json
{
  "queries": [
    {
      "refId": "A",
      "datasource": {"type": "prometheus", "uid": "<uid>"},
      "expr": "up{job=\"node\"}",
      "instant": true,
      "range": false,
      "intervalMs": 60000,
      "maxDataPoints": 1000
    }
  ],
  "from": "now-1h",
  "to": "now"
}
```

Dashboard source is declaratively generated by `modules/nixos/grafana.nix`.
Never make a dashboard-only UI edit and treat it as durable configuration.

## Datasources

Discover datasource UIDs instead of guessing them:

```bash
op run --env-file=/tmp/opencode/grafana.op.env -- sh -c '
  curl -fsS -u "$GRAFANA_USER:$GRAFANA_PASSWORD" \
    "$GRAFANA_URL/api/datasources" |
    jq ".[] | {name, uid, type, url, isDefault}"
'
```

Prometheus is the default datasource. Loki's provisioned UID is currently
`P8E80F9AEF21F6940`, but verify it through the API before scripting against it.

## Querying Through Grafana

Use `/api/ds/query` to query both Prometheus and Loki without reaching their
private `drlight` ports directly. A datasource query must include the datasource
UID, `refId`, time range, and query expression.

```bash
op run --env-file=/tmp/opencode/grafana.op.env -- sh -c '
  curl -fsS -u "$GRAFANA_USER:$GRAFANA_PASSWORD" \
    -H "Content-Type: application/json" \
    -X POST "$GRAFANA_URL/api/ds/query" \
    -d @query.json | jq .
'
```

If a panel is blank, compare the live panel target from the dashboard API with
the exact `/api/ds/query` response before changing Nix.

## Common Mistakes

- Treating a successful HTTP response as proof that the frame contains rows.
  Inspect `results.<refId>.frames` and errors.
- Joining Prometheus series on a label before applying the `labelsToFields`
  transformation.
- Using range queries for current per-entity Prometheus tables.
- Querying Loki event fields at the outer journald JSON level. The worker nests
  JSON in `message`. Use `| json | line_format "{{.message}}" | json` first.
- Editing provisioned dashboards through the API. Use the development copy.
- Editing dashboards in the UI instead of `modules/nixos/grafana.nix`.
- Using SSH as the first diagnostic path. Use SSH only when the required API
  evidence is unavailable and record the reason.
