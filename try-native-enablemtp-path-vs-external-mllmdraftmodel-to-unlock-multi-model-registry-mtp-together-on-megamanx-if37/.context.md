## Why
instance-options.nix exposes TWO separate, non-overlapping MTP mechanisms:

1. `enableMtp = true` / `mtpNumDraftTokens` / `mtpOptimistic` — described as
   "for models with built-in MTP heads such as Qwen3.8" and, critically, does
   NOT force single-model mode — it's a plain CLI flag added alongside
   `--models-config` in lib.nix (line ~161-163).
2. `mllmDraftModel` / `mllmDraftKind` / `mllmDraftBlockSize` — external mlx-vlm
   draft model, which DOES force single-model mode (drops `--models-config`
   entirely, per lib.nix lines 144-146).

MegamanX's live config uses mechanism #2 (external draft model:
`mlx-community/Qwen3.8-27B-MTP-8bit`), which is presumably why it's stuck in
single-model mode. But Qwen3.8-27B is explicitly called out in option #1's own
description as having "built-in MTP heads." It is not yet confirmed whether
switching to `enableMtp = true` (mechanism #1, no external draft model) gives
the SAME speculative-decoding speedup while ALSO allowing `--models-config`
multi-model registry mode to stay active -- which would let MegamanX serve
qwen3.8-27b AND gemma4-e4b from the SAME instance/port with MTP still active on
qwen, instead of needing two separate launchd daemons/ports as today.

## What to do
1. Read vllm-mlx upstream docs/source for exactly what `--enable-mtp` does vs
   `--mllm-draft-model` for Qwen3.8 specifically — are they two implementations
   of the same speculative-decoding idea (built-in head vs external drafter),
   and is the built-in-head path expected to be faster/slower/equivalent?
2. On MegamanX (or a scratch instance on a spare port), try:
   ```nix
   vllmMlx = {
     enable = true;
     enableMtp = true;
     mtpNumDraftTokens = 1;   # start conservative; the option's own docs say
                              # "higher values increase speed when acceptance
                              # rate is high" -- measure before raising
     models = {
       "qwen3.8-27b" = { path = "mlx-community/Qwen3.8-27B-8bit"; ... };
       "gemma4-e4b" = { path = "mlx-community/gemma-4-e4b-it-4bit"; ... };
     };
   };
   ```
   i.e. drop `mllmDraftModel`/`mllmDraftKind`/`mllmDraftBlockSize` entirely and
   rely on `--models-config` + `--enable-mtp` together, merging what is today
   two separate instances (ports 8300 + 8301) into one multi-model registry
3. Benchmark tok/s against the current external-draft-model setup
4. If native `enableMtp` works as well or better AND keeps multi-model mode:
   this could let MegamanX simplify to a single instance/port serving both
   models with MTP active, freeing up the 24GB currently budgeted separately
   for the gemma instance
